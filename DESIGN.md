# DESIGN.md — дизайн-система Autism Connect

Документ фиксирует визуальный язык, показанный на согласованных рендерах (главный экран ребёнка, кабинет родителя, визуальное расписание), в виде конкретных токенов и спецификаций компонентов. Claude Code должен использовать значения из этого файла буквально — не приближенно "на глаз".

**Важно про шрифт:** рендеры были построены на внутреннем шрифте интерфейса Claude (Anthropic Sans), который является проприетарным и не может использоваться в сторонних продуктах. Ниже даётся open-source замена, максимально близкая по характеру (геометричный, скруглённый, дружелюбный). Всё остальное — цвета, отступы, радиусы, состояния — воспроизведено буквально из рендеров.

---

## 1. Философия

- **Плоский дизайн.** Никаких градиентов, теней (кроме функционального focus-ring), размытий, неоновых эффектов.
- **Просторно.** Много воздуха между элементами, минимум визуального шума.
- **Скруглённые формы.** Мягкие углы во всём — от кнопок до карточек — создают ощущение безопасности и дружелюбности, что критично для целевой аудитории.
- **Sentence case всегда.** Никакого CAPS LOCK и Title Case, даже в заголовках и на карточках ("Позавтракать", не "ПОЗАВТРАКАТЬ").
- **Только два начертания шрифта:** обычный (400) и полужирный (500). Никогда не использовать 600/700 — визуально тяжело для целевой аудитории.
- **Цвет несёт смысл, а не декор.** Каждая категория карточек имеет закреплённый цвет; цвет состояния (выполнено/сейчас/предстоит) переиспользуется одинаково во всём приложении.

---

## 2. Шрифт

```css
--font-sans: 'Nunito', 'Inter', system-ui, sans-serif;
```

`Nunito` — рекомендация по умолчанию (скруглённые начертания, тёплый и дружелюбный характер, хорошо читается детьми), подключается через Google Fonts. Если нужна более нейтральная альтернатива для родительского кабинета — `Inter`. Не смешивать больше двух семейств в одном приложении.

## 3. Цветовые токены

### 3.1 Нейтральные поверхности

```css
--surface-page:   #F7F6F2;  /* фон всего приложения */
--surface-panel:  #FFFFFF;  /* карточки, панели, конструктор предложения */
--surface-muted:  #F1EFE8;  /* второстепенные панели, неактивные пилюли категорий */
--border:         #D3D1C7;  /* тонкая граница, 1px */
--text-primary:   #2C2C2A;  /* основной текст */
--text-secondary: #5F5E5A;  /* второстепенный текст, неактивные категории */
--text-muted:     #888780;  /* подписи, метки, будущие шаги расписания */
```

### 3.2 Акцентный цвет (выбор, кнопка озвучивания, текущий шаг)

```css
--accent-50:  #E6F1FB;  /* фон выбранной карточки в конструкторе, фон текущего шага расписания */
--accent-600: #185FA5;  /* текст/иконка на accent-50 */
--accent-fill: #378ADD; /* заливка кнопки "Озвучить" */
--accent-border: #185FA5; /* граница текущего шага расписания, 2px */
```

### 3.3 Статус "выполнено" (расписание)

```css
--success-50:  #EAF3DE;
--success-800: #27500A;  /* текст/иконка/галочка на success-50 */
```

### 3.4 Цвета категорий карточек

Каждая категория закреплена за одним цветом на весь проект — не менять произвольно. Формула везде одинаковая: **фон = 100-й тон, текст/иконка = 800-й тон той же палитры.**

| Категория | Фон (100) | Текст/иконка (800) |
|---|---|---|
| Еда | `#F5C4B3` | `#712B13` |
| Напитки | `#9FE1CB` | `#085041` |
| Игрушки | `#CECBF6` | `#3C3489` |
| Семья | `#F4C0D1` | `#72243E` |
| Действия | `#F7C1C1` | `#791F1F` |
| Эмоции | `#FAC775` | `#633806` |
| Животные | `#C0DD97` | `#27500A` |
| Одежда | `#D3D1C7` | `#444441` |
| Транспорт | `#B5D4F4` | `#0C447C` |
| Природа | см. примечание ниже | |

> В библиотеке 10 категорий (раздел 6.3 ТЗ), а в базовой палитре — 9 самостоятельных цветов. Для "Природы" не выдумывать десятый случайный цвет — либо расширить палитру одним согласованным дополнительным оттенком, либо переиспользовать "Животные" (зелёный) с другой иконкой, раз обе категории семантически близки к природе. Финальное решение — за дизайнером/владельцем продукта, не автогенерировать самостоятельно.

**Редакция 3 механики:** категории теперь — глаголы ("Дай", "Болит", "Идти", "Есть", "Мыться"), формула фон-100/текст-800 применяется к ним точно так же (конкретные hex закреплены в `packages/database/prisma/seed-data.ts`, не дублируются здесь). Отдельно зафиксированы цвета для служебных карточек Да/Нет (не категорий — это `isSystemCard`, живут в своей sticky-панели, см. §6.8):

| Карточка | Фон | Текст/иконка |
|---|---|---|
| Да | `#F6C6C6` | `#7A1414` |
| Нет | `#C6D8FA` | `#1E3A8A` |

Исходный (несветлённый) цвет карточки в БД: Да — `#B91C1C` (красный), Нет — `#1D4ED8` (синий); формула светления та же, что и для категорий (см. `resolveCategoryColorToken` в `packages/ui`).

## 4. Радиусы и отступы

```css
--radius-sm:  10px;  /* мелкие пилюли, кнопки в конструкторе предложения */
--radius-md:  14px;  /* карточка (Card), плитка шага расписания */
--radius-lg:  16px;  /* панель конструктора предложения, контейнер сетки */
--radius-full: 999px; /* пилюли категорий */

--gap-xs: 8px;
--gap-sm: 10px;
--gap-md: 16px;
--gap-lg: 24px;

--pad-tile: 16px 8px;      /* внутренний отступ карточки/плитки шага */
--pad-panel: 20px;         /* внутренний отступ панелей */
```

Полноэкранные контейнеры (сам экран приложения) — без скругления, скругление только у вложенных панелей и элементов.

## 5. Типографический масштаб

| Назначение | Размер | Начертание |
|---|---|---|
| Число-метрика (кабинет родителя) | 24px | 500 |
| Подпись на карточке (production, не мокап-масштаб!) | **20–22px** | 500 |
| Кнопка "Озвучить" | 16px | 500 |
| Пилюля категории | 14px | 400 / 500 (активная) |
| Подпись метрики, заголовок блока | 13–14px | 500 |
| Второстепенная подпись, ось графика | 11–13px | 400 |

**Важное отличие от рендера:** на демо-рендерах подпись карточки была уменьшена до 14px, так как рендер сжат в canvas шириной 680px. В реальном приложении на планшете (раздел 1 ТЗ — приоритет Android-планшеты) подпись карточки должна быть **не меньше 20px**, а сама карточка — не меньше **96×96px** (это строже даже, чем зафиксированные ранее 88px в `ARCHITECTURE.md`, т.к. рендер подтвердил визуальный масштаб "одна карточка = треть ширины экрана планшета", а не мелкая иконка).

## 6. Спецификация компонентов

### 6.1 Панель конструктора предложения

- Контейнер: `--surface-muted` фон, `--radius-lg`, `--pad-panel`, `display: flex`.
- Каждое слово — пилюля: невыбранное — `--surface-panel` фон + `--border` граница; выбранная карточка — `--accent-50` фон + `--accent-600` текст, без границы.
- Кнопка "Озвучить" — справа, `--accent-fill` заливка, белый текст, иконка динамика слева от текста, `--radius-sm`.

### 6.2 Пилюля категории

- Неактивная: `--surface-muted` фон, `--text-secondary` текст, `--radius-full`.
- Активная: фон и текст — 100/800 тон цвета этой категории (см. таблицу 3.4), `--radius-full`.
- Иконка слева от подписи, 16px.
- **Редакция 3, `isPrimary`:** пилюля категории "Дай" всегда в акцентном (100/800) цвете, даже когда не активна — плюс граница 2px тем же 800-тоном, чтобы отличаться от обычной активной пилюли визуально (не просто "всегда активна на вид").

### 6.3 Карточка (Card tile)

- Фон: 100-й тон цвета категории.
- Иконка: 32px (в мокапе), в production — пропорционально размеру карточки, но не меньше 32px; цвет — 800-й тон той же категории.
- Подпись: под иконкой, по центру, 800-й тон, 500 начертание.
- `--radius-md`, `--pad-tile`.
- Сетка: `grid-template-columns: repeat(auto-fit, minmax(140px, 1fr))`, `gap: var(--gap-sm)` — не фиксировать жёстко 4 колонки, чтобы адаптироваться под разные планшеты.

### 6.4 Плитка шага расписания

Три состояния, различаются только цветом и наличием элементов — геометрия одинаковая:

| Состояние | Фон | Текст/иконка | Доп. элемент |
|---|---|---|---|
| Выполнено | `--success-50` | `--success-800` | галочка `ti-check` в правом верхнем углу |
| Текущий шаг | `--accent-50` | `--accent-600` | граница 2px `--accent-border` |
| Предстоит | `--surface-muted` | `--text-muted` | нет |

Горизонтальная прокручиваемая лента, `gap: var(--gap-sm)`, ширина плитки ~120–140px (масштабировать под экран).

### 6.5 Метрическая карточка (кабинет родителя)

- Фон: `--surface-panel`, без границы, `--radius-md`, `--pad-panel` уменьшенный до `16px`.
- Подпись сверху: 13px, `--text-secondary`.
- Число снизу: 24px, 500, `--text-primary`.

### 6.6 Столбчатый график активности

- Столбцы: `--accent-50` заливка для обычных дней, `--accent-fill` — для дня с максимальной активностью (единственный акцент, не раскрашивать каждый столбец отдельным цветом).
- Подписи дней недели под столбцами: 11px, `--text-muted`.

### 6.7 Аватар-инициалы (карточка ребёнка)

- Круг 40–44px, фон `--accent-50`, текст-инициалы `--accent-600`, 500 начертание, 14px.

### 6.8 Sticky-панель Да/Нет (редакция 3, `<YesNoStickyPanel>`)

- Отдельная панель, прижатая к низу экрана ребёнка (`position: sticky; bottom: 0`), **не** часть сетки категории.
- Фон `--surface-panel`, верхняя граница 1px `--border`.
- Две крупные пилюли-кнопки (`--radius-full`), 18px/500, с иконкой (`ti-check` для Да, `ti-x` для Нет) слева от подписи.
- Цвета — из таблицы §3.4 (Да/Нет), приходят с самих карточек через API, не хардкодятся в компоненте.
- Виден на всех вкладках-категориях; скрыт на вкладке "Расписание".

### 6.9 Режим редактирования (редакция 3, §A.7 ТЗ)

- Переключатель — круглая иконка-кнопка (карандаш, `ti-pencil`) в правом краю строки категорий; неактивна — `--surface-muted`/`--text-secondary`, активна — `--accent-50`/`--accent-600`.
- В активном режиме на каждой карточке (`<CardButton onDelete>`) появляется крестик-бейдж: круг 32px, `--danger` фон (см. §3.5 в существующей палитре `theme/tokens.ts`), белая иконка `ti-x`, смещён на -8px от верхнего правого угла карточки — не меняет геометрию самой карточки.
- В конце сетки — пунктирная плитка `<AddCardTile>`, тех же размеров и `--radius-md`, что и обычная карточка: 2px пунктирная `--border`, иконка `ti-plus` 28px + подпись "Добавить" (14px/400) по центру, `--text-muted`.
- Никакой отдельной "админской" визуальной темы для режима редактирования — те же токены, что и везде в зоне ребёнка.

## 7. Иконки

Используется набор **Tabler Icons (outline)** — открытый, бесплатный, единообразный стиль обводки. Не смешивать с другими наборами иконок или эмодзи (эмодзи в ТЗ явно нежелательны для консистентности рендеринга на разных устройствах — раздел 8 ТЗ косвенно требует предсказуемого визуала).

Соответствие категория → иконка (расширять по мере роста библиотеки карточек):

| Категория | Иконка |
|---|---|
| Еда | `ti-apple`, `ti-cherry`, `ti-bread`, `ti-egg`, `ti-carrot` |
| Напитки | `ti-milk`, `ti-cup` |
| Семья | `ti-users` |
| Эмоции | `ti-mood-smile` (и другие `ti-mood-*` под конкретные эмоции) |
| Транспорт | `ti-car` |
| Действия | подбирать под конкретное действие, без единого паттерна |

## 8. Что переносить буквально, а что — адаптировать

**Переносить один в один:** цветовые токены (раздел 3), формула "фон 100 / текст 800" для категорий, скругления (раздел 4), геометрия компонентов (раздел 6), правило sentence case, ограничение в два начертания шрифта.

**Адаптировать под реальное устройство:** абсолютные размеры карточек и текста (раздел 5) — рендеры были сжаты под демо-canvas 680px, реальный планшетный экран требует увеличения пропорционально, с сохранением того же визуального соотношения "карточка большая, текст крупный, воздуха много".

**Не переносить:** шрифт Anthropic Sans (проприетарный) — заменяется на `Nunito`/`Inter` (раздел 2).
